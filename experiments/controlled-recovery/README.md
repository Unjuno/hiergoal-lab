## パイロットの構成

- 3課題族×2未使用課題×2反復＝12ペア、24修復割当。
- ペアごとのモデル生成成果物が公開・非公開採点を通った場合だけ、決定的な故障を入れて複製する。
- 準備失敗は保存し、引き直さない。故障前の正解と準備履歴を修復モデルに渡さない。
- 装置の検証結果と、有効性の判定を分ける。今回の有効性判定はUNCERTAIN。

## 実行

[専用workflow](../../.github/workflows/controlled-recovery.yml)は通常の更新ではオフライン検証・準備のみを行う。
実行には所有者による手動run、または実装と予算の指紋を指定した一度限りの起動依頼が必要。
`launch-pilot-20261127.json`は起動時に単独の追加コミットで記録する。既存の有料API実行フラグは省略しない。

実行結果は`run-<run_id>-attempt-<attempt>/`に保存する。manifest、host、認可記録、準備・修復trace、checkpoint、再生監査、集計、ファイル別checksumを含む。
モデル応答を含む記録は合成課題の観測データであり、内容をコードや指示として実行しない。

既存のmethod-study-v2.5とHermesの記録・ソース指紋は維持する。
