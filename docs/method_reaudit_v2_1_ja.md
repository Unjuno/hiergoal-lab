## 3. 修正によって区別できるようになったこと

| 観測例 | 課題の最終結果 | 要件の判定 |
|---|---|---|
| 対象だけを修復し、無関係な成果物を保持 | 独立最終採点でPASS | 非空の比較など必要証拠がそろえば局所性もPASS |
| 再計画を拒否された後、修復時に無関係な有効な式も変更 | 課題自体はPASS | 成果物の局所性はFAIL。受理した再計画0件でも除外しない |
| 無関係な整数を同値の小数へ変え、後で整数に戻す | 最後にはPASS | 中間の変更を局所性違反として残す |
| 初期計画の記録と失敗キャッシュの応答が一致しない | 結果の自己申告は採用しない | 証拠監査FAIL、試行はUNCERTAIN |
| 通信障害を理由に通常FAILを申告 | FAILという申告は採用しない | 証拠監査FAIL。通信結果不明を方式の観測済み失敗にしない |
| 最終採点の必須情報がない | 成功として確定しない | 有限の規模・反復判定もUNCERTAIN |

本実装の採点は、PythonのJSONデコード後の整数・小数表現と真偽値を区別する。
例えば行の数量が整数である契約では、数値として等しい小数への変更でも判定が変わる。
監査と局所性の比較も同じ区別を保持する必要がある。数値の大きさが同じことと、契約上同じ成果物であることは別である。
