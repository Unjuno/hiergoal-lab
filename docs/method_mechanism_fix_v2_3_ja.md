# Mechanism実験の計画形式と重複入力の修正 — v2.3

## 原因と修正

- 計画形式違反12試行（共有計画3件）: 認証ゲートの命令に文字列ではなくオブジェクトが返された。初期計画のResponses API出力形式を厳格なJSON Schemaに変更。指定階層では全ゲートのキーを必須とし各値を文字列型にする。自由階層でも各命令・タイトルを文字列に制約する。文字数・依存関係・ゲート被覆の従来の検証は維持する。修復・再抽選・暗黙のフォールバックはしない。モデルが厳格形式を受理するかは実APIで未確認。
- トークン予算超過2試行: 現在のタスク仕様とルート契約、およびゲート・依存関係の厳密に同じ値がAPI入力に重複していた。wire_inputは重複のみを参照に置換する。動的に異なる値、成果物、全公開判定、履歴は保持する。3方式に同じ変換を適用する。全論理入力を従来通りログ保存し、実API応答のwire_requestには入力JSONバイト数・入力ハッシュ・出力形式ハッシュを記録し、再生監査で検証する。
- 旧プロトコルの変更・再ラベル付けはしない。v2.3の新規manifestを作成する。採点、障害介入、比較群、スケジュール、予算上限、効果判定閾値、費用承認規則を変更しない。
