# 実際の Hermes Agent による階層的サブゴール実行：単一ケース観察プロトコル

## 目的と実行条件

研究の目的は「実際の Hermes Agent が、中期・短期サブゴールを長期目標に結びつけ、コード修正と検証を実行するか」を観察すること。比較群は設けない。H-JEPA の実装や効果の再現ではない。

- 実行対象：Hermes Agent CLI、OpenAI API (openai-api)、gpt-6-luna、reasoning=low
- 操作：file / terminal / todo ツールセット
- 実課題：Python CSV 台帳のバグ修正。元コードと可視テストは fixtures、追加の独立テストは evaluation に固定
- 事前確認：元のコードが可視テストで不合格であること
- 実行上限：20 iteration、900秒。これは API 課金に対するハードストップではない
- 保持：全イベント JSONL、最終コード差分、計画書、実行コマンド、別系統の評価結果
- 検証：API使用前にオフラインテストを実施。実課金実験は人間が明示的に起動する
- 機密：APIキーをリポジトリ・GitHub Issue・公開ログに保存しない

## H / T / D / C / U

**H（仮説）:** 指示された1件の課題で Hermes は親子関係・検証条件を持つ目標計画を作成し、ソースを修正して独立評価を満たせる。これは一般化可能な改善率を主張する仮説ではない。

**T（最小検証）:** 同一ホストで1課題×1実行。元状態のテスト不合格、実行ログ、計画ファイル、独立評価を収集。逐次停止は1実行で終了。追加費用と実験拡張は手動判断。

**D（判定）:** PASS = Hermes正常終了 + 最終stream結果あり + 可視テストPASS + 独立評価PASS。FAIL = 評価不合格または明確な実行失敗。UNCERTAIN = タイムアウト、ストリーム欠落、解析不全。目標階層の妥当性は結果とは独立に人手レビューする。

**C（破れ方）:** 計画ファイルだけ生成し実行では使わない、局所的修正しか行わない、隠れたテストを満たさない、目的を無断変更する、gatewayがクライアントタイムアウト後も動く、外部モデル呼び出し分が計上されない。

**U（不確かさ）:** モデルの非決定性、Hermesのバージョンと設定、API課金仕様、token記録の欠測、工具・ホストの差。初回は統計的推定を行わず、不確かさの合成値 u_c と拡張係数 k を算定しない。モデル料金は実測請求と区別する。

## 変数表

| 記号 | 意味（日本語） | 単位（SI） | 定義 | 定義域・前提 | 型 |
|---|---|---|---|---|---|
| N_in | 入力トークンの報告件数 | 1（無次元） | 最終JSONLの tokens.input | 非負整数、欠測可 | 整数スカラー |
| N_out | 出力トークンの報告件数 | 1（無次元） | 最終JSONLの tokens.output | 非負整数、欠測可 | 整数スカラー |
| p_in | 入力名目単価 | USD/10^6 tokens（SI外） | Luna Standard短文脈 0.10 | 料金改定・処理種別で変動 | 実数スカラー |
| p_out | 出力名目単価 | USD/10^6 tokens（SI外） | Luna Standard短文脈 0.50 | 同上 | 実数スカラー |
| C_est | 可視トークンのみの推定費用 | USD（SI外） | (N_in*p_in + N_out*p_out)/10^6 | 課金額と一致する保証なし | 実数スカラー |
| T | 計測所要時間 | s | ホスト単調時計差 | 0以上 | 実数スカラー |

**次元チェック:** 無次元の token 件数 × USD/token = USD。所要時間 T の単位は秒で、価格計算には混入しない。

**数値例（仮定値）:** 入力10万件・出力2万件なら 0.10×0.1 + 0.50×0.02 = 0.02 USD。キャッシュ処理、長文脈割増、補助呼び出し等の影響は含まれない。

## 学際的観点

- AI計画：階層的目標表現と再計画、実行トレースと計画の照合
- ソフトウェア工学：実コード修正、回帰テスト、独立の受け入れ判定
- 実験計量：条件記録、測定欠損、推定費用と請求費用の区別
