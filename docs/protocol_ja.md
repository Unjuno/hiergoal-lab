# Hermes Agent 階層的サブゴール実行：実験プロトコル v1

## 1. 目的・研究命題

Hermes Agent の実CLIを外部オーケストレーターから段階的に実行し、長期目標→中期マイルストーン→短期タスクを使って実際のPythonコード修正を遂行できるか検証する。

**事実：** GitHub Actionsで模擬Hermesを使う無課金の統合テストに成功した。これ自体はOpenAI API接続実績でも、現実のHermesでのタスク達成実績でもない。

**仮説：** 実際のHermesが、有効な計画を生成し、依存関係に沿って短期タスクを処理し、失敗時に親の達成条件を変えずにタスクを再計画できる。

この設計はH-JEPAの「上位の抽象的目標から下位の実行目標を定める」という着想を参照するが、JEPAの学習・潜在状態・シミュレーションは実装していない。H-JEPA論文の数値をHermesの実測結果として引用してはならない。

## 2. 実装内容と研究条件

| 層 | 所有者 | 状態・検証 |
|---|---|---|
| 長期ゴール G0 | 実験者 | コードで固定。最終の独立評価を通るまで完了しない |
| 中期マイルストーン M1..M4 | Hermesが提案、Pythonが検証 | 子の短期目標の完了結果から状態を決定 |
| 短期目標 S1..S8 | Hermesが提案、Pythonが検証 | 独立テストの結果によって完了/失敗を確定 |
| 再計画後の短期目標 S*r1 | Hermesが代替案を提案、Pythonが置換 | 元の受け入れ条件を維持し、依存関係を更新 |

受け入れ条件は実験者が固定した6種。モデルは条件の割り当てと実行方法を提案できるが、条件を変更・削除・増設できない。依存グラフの循環、達成条件の重複、欠落、不明な依存は起動前に拒否する。

独立評価はエージェントが編集するworkspaceの外から実行し、元の可視テストが編集されていないことも検査する。モデルの自己申告による完了は認めない。

実行中の全Hermes呼び出しは、コマンド引数、実行プロンプト、stream-json、診断ログ、判定結果をローカルの runs/ に保存する。

## 3. H / T / D / C / U

**H（反証可能仮説）:** 既定の1件のPython修正タスクで、Hermesが受け入れ条件を満たす階層的計画を生成し、短期目標を順に実行し、最終独立テスト6件および可視テスト3件を全て通す。失敗した短期目標は、既定回数内で親目標を不変にして修正できる。

**T（最小検証）:** n_min=1タスク×1実行。macOS/Linux/WSL2、Python 3.11以上、Hermes CLIとOpenAI Direct API、モデル gpt-6-luna、reasoning=low、toolsets=file,terminal,todo。計画に最大4中期目標、最大8短期目標。最大12モデル呼び出し、呼び出し当たり18ツール反復、最大2再計画、呼び出しタイムアウト600 s。追加試行や予算増額は人間が決定。API料金を使う場合は、本人が --ack-unsandboxed でローカルツールの危険を明示的に承認する。

**D（合否判定）:**
- PASS: 各短期目標の決定論的受け入れ条件を満たし、全6件の独立テスト・全3件の可視テストがPASSし、元の可視テストが不変。
- FAIL: 実行・モデル計画の確定的失敗、受け入れテスト不合格、再計画上限到達、依存関係の矛盾。
- UNCERTAIN: ストリームの最終イベント欠落、タイムアウト、トークン計測欠損、ローカルの費用ガード到達など結果を確定できない状態。

**C（対立仮説・破れ方）:** (i) ツール結果だけで計画を生成して実行に反映しない、(ii) ある短期目標の修正が別の達成条件を壊す、(iii) モデルがJSON計画形式に従わない、(iv) Hermesのgatewayがクライアント終了後も実行して費用が増える、(v) 制約環境によるタスク失敗を階層化そのものの失敗と混同する。

**U（不確実性）:** API課金レート、キャッシュ、補助モデル呼び出し、トークンメーター欠測、ホストHW、実行時点のHermesバージョン、モデル非決定性が主要誤差源。単一ケースなので成功率の統計誤差・合成標準不確かさ u_c・包含係数 k は算定対象外（同定不能）。実費はOpenAI Platformの請求情報で別途確認する。

## 4. 費用推定と変数表

短文脈Standard料金の概算に限定する。

\[
C_{\mathrm{est}}=\frac{p_{\mathrm{in}}N_{\mathrm{in}}+p_{\mathrm{out}}N_{\mathrm{out}}}{10^6}.
\]

| 変数 | 意味（日本語） | 単位（SI） | 定義 | 範囲・前提 | 型 |
|---|---|---|---|---|---|
| C_est | 記録されたモデル入出力の概算費用 | USD（SI非対応） | 上式 | 0以上、実請求額と一致しない | 実数スカラー |
| p_in | Lunaの入力名目単価 | USD/10^6トークン（SI非対応） | 0.10 | Standard、短文脈、料金変更あり | 実数スカラー |
| p_out | Lunaの出力名目単価 | USD/10^6トークン（SI非対応） | 0.50 | 同上 | 実数スカラー |
| N_in | 記録された入力トークン数 | 1（無次元の個数） | stream-jsonのtokens.inputの和 | 0以上、欠測あり | 整数スカラー |
| N_out | 記録された出力トークン数 | 1（無次元の個数） | stream-jsonのtokens.outputの和 | 0以上、欠測あり | 整数スカラー |

**次元チェック：** トークン件数 × (USD / 百万トークン) ÷ 10^6の正規化 = USD。USDはSI単位ではなく貨幣額である。

**仮定した数値例：** 入力10万トークン、出力2万トークンなら概算0.02 USD（キャッシュ・超長文脈・補助呼び出し等を無視）。実費を示す例ではない。

## 5. 運用順序

1. git cloneし、python3 -m unittest discover -s tests -v と python3 -m hiergoal.controller --dry-run を実行する（無料）。
2. Hermesの doctor/model 設定でOpenAI API Directを選択する。APIキーはGit管理対象に含めない。
3. 安全な隔離環境で python3 -m hiergoal.controller --ack-unsandboxed --pilot-budget-usd 3 を1回実行する。
4. runs/*/state.json, records.json, 各 *.stream.jsonl, gate-*.json を確認し、誤成功判定の有無を検査する。
5. 公開前に生ログの機密情報を伏せ、Hermesバージョン・HW/OS・実行日時・API請求情報を添える。
6. 結果が再現可能となった段階で、HermesのIssue #156054に結果のURLと制限事項を記録する。
