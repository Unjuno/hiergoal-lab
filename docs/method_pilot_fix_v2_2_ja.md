実行器がパッチ適用前の葉を再計画判断に用い、次の反復でパッチ適用後の公開判定から別の葉を選ぶことがあった。
例えば、adjusted の修復時に expressions 全体を部分的な辞書で置換すると、base の達成証拠が失効する。
旧監査は adjusted に対する許可で base を再計画する要求を正しく拒否するため、実行時の最終採点が合格しても記録を UNCERTAIN とする。

修正: パッチ適用後の公開判定と依存関係から得る active_leaf を再計画判断に使う。
監査でも同じパッチを再適用してから対象を再計算し、別の葉への不正な許可は引き続き拒否する。
成果物の置換規則、採点器、比較方式、試行数、資源上限、効果判定閾値は変更しない。
再計画が必要かどうかは従来の公開ゲート進展規則を維持する。

tests/test_study_upstream_regression.py は公開合格、環境変化、部分的な辞書置換、上流ゲートの失効、再計画、独立採点、再生監査の全経路をオフラインで再現する。
旧実装では監査 FAIL、新実装では PASS となる。
対象を過去の葉へ戻したログはハッシュを再計算しても監査 FAIL になることを確認する。

実モデルへの新規要求は行わない。旧記録の改変・再ラベル付け・旧版との成績の混合は行わない。
v2.2 の新規 manifest を作り、次の実API pilotで修正後の実際の計測経路を検証する。
